# Танковый фронт

Браузерная 3D-игра для **2–8 настоящих игроков**, без ботов и регистрации. Простое меню: ник → «Играть» → автоматическое подключение к комнате. Чтобы друзья гарантированно попали в ваш бой, отправьте им ссылку из кнопки «Пригласить».

Клиент — TypeScript, Vite, Three.js. Сервер — Node.js, TypeScript, WebSocket. Все модели и карта созданы процедурно, внешних картинок, моделей, шрифтов, API и платных сервисов в игре нет.

**Две работающие независимые копии:** [Render](https://tank-front.onrender.com) и [Enzonic через бесплатный шлюз Cloudflare](https://tank-front-enzonic.mgladkov669.workers.dev). У копий отдельные комнаты: друзьям нужно открыть один и тот же сайт. Исходный репозиторий — [tanks-online/tank-front](https://github.com/tanks-online/tank-front). Обе копии прошли проверку HTTPS/WSS, двух подключений и настоящего браузера. Финальная приёмка друзьями с двух физических компьютеров ещё нужна. [Публикация и ограничения](docs/TWO-HOSTS.md).

## Быстрый локальный запуск

Установите Node.js 24 LTS и распакуйте проект. В корне:

```powershell
npm run setup
```

Скопируйте `client/.env.example` в `client/.env.local`. Адрес для локального запуска уже заполнен: `ws://localhost:3000/ws`. Сервер по умолчанию разрешает localhost на портах 5173/4173.

В одном терминале:

```powershell
npm run dev:server
```

В другом:

```powershell
npm run dev:client
```

Откройте **http://localhost:5173/**. Введите ник и нажмите «Играть». Откройте этот же адрес во втором браузере или вкладке, укажите другой ник и нажмите «Играть» — сервер подберёт ту же свободную комнату. Для браузера нужен WebGL 2 и включённое аппаратное ускорение.

**Локальный адрес работает на вашем компьютере.** Друзьям отправьте одну из двух публичных ссылок выше. Для собственной копии выполните [публикацию](docs/TWO-HOSTS.md). Сборка использует `VITE_SERVER_URL=/ws` для подключения к текущему сайту.

## Игра

- W/S — вперёд/назад, A/D — поворот корпуса; мышь — башня; ЛКМ — огонь. TAB расширяет таблицу, Escape открывает настройки.
- Матч начинается при двух подключённых людях, длится 3 минуты. Побеждает большее число уничтожений; при равенстве — меньшее число смертей; одинаковый результат — ничья.
- После уничтожения танк возрождается через 3 секунды. Препятствия и границы блокируют движение и снаряды. При возрождении выбирается свободная точка вдали от соперников.
- В настройках доступны звук, качество и танк для следующего входа. Ник и настройки хранятся в `localStorage` этого браузера.
- Сервер восстанавливает сессию при кратком разрыве связи в течение 30 секунд. После перезапуска сервера комнаты и результаты теряются. Игрок получает сообщение, что нужна новая комната.
- «Играть» сначала заполняет подходящий незавершённый бой. Если подходящих комнат нет, создаёт новую. Максимум 4 комнаты по 8 игроков на экземпляр сервера.

| Танк | HP | Скорость, ед/с | Урон | Перезарядка |
| --- | ---: | ---: | ---: | ---: |
| Стриж — лёгкий | 75 | 10 | 20 | 0,35 с |
| Бастион — средний | 110 | 7 | 30 | 0,6 с |
| Молот — тяжёлый | 160 | 5 | 45 | 1 с |

Карта «Песчаное депо» — арена 80 × 64 с семью непростреливаемыми укрытиями. Изменения физики и характеристик в `server/src/world.ts`; геометрия карты приходит клиенту с сервера.

## Сборка и проверки

После создания `client/.env.local`:

```powershell
npm test
npm run build
```

`client/dist` содержит обычные статические HTML/CSS/JS. Относительный Vite `base: './'` и импорты сохраняют корректные пути к ресурсам. `server/dist` — Node.js-программа. Для размещения сайта и сервера на одном адресе используйте `npm run build:hosted`, затем `STATIC_DIR=../client/dist` и корневой `npm start`; подробности для PowerShell и хостингов — в [инструкции](docs/TWO-HOSTS.md).

Автотесты проверяют серверную симуляцию и настоящие WebSocket-соединения: 2 игрока, движение, урон, уничтожение, возрождение, завершение матча, 8 игроков, автоматический подбор, лимиты, Origin, восстановление связи. Они не подменяют проверку с двух физических компьютеров через интернет. Её порядок и текущий статус — в [ACCEPTANCE.md](docs/ACCEPTANCE.md).

## Бесплатная публикация

[Пошаговая инструкция](docs/TWO-HOSTS.md): один исходный репозиторий GitHub → два независимых сайта с WebSocket-серверами, один на Render Free, другой на Enzonic Free.

| Где | Настройка |
| --- | --- |
| Render | Root пустой, build `npm run setup && npm run build:hosted`, start `npm start`, план **Free** |
| Render environment | `NODE_VERSION=24`, `NODE_ENV=production`, `NPM_CONFIG_INCLUDE=dev`, `VITE_SERVER_URL=/ws`, `STATIC_DIR=../client/dist`; `PORT` и `RENDER_EXTERNAL_URL` выдаёт платформа |
| Enzonic | Node.js generic **Free**, Node.js 22.14+, назначенный панелью порт; предпочтительно runtime-архив `tank-front-enzonic.tar.gz`, затем `npm ci --omit=dev` и `npm start` из его корня |
| Enzonic environment для runtime-архива | `NODE_ENV=production`, `STATIC_DIR=public`, назначенный `PORT`, точный `PUBLIC_URL=https://HOST` либо `ALLOWED_ORIGINS=https://HOST`; `/ws` уже встроен в клиент |

`render.yaml` фиксирует один бесплатный сайт Render. Платные услуги и карта при размещении не подключались. Если другой аккаунт требует карту для проверки, остановитесь. Нативный бесплатный поддомен Enzonic не прошёл TLS-проверку: сертификат не соответствует его имени. Поэтому `gateway/worker.js` принимает HTTPS/WSS на Workers Free и передаёт запросы на Node.js Enzonic. **Участок Cloudflare → Enzonic использует HTTP/WS без TLS.** Это описано вместе с квотами и точными настройками в [инструкции](docs/TWO-HOSTS.md).

После размещения проверьте каждую копию из корня (нужны установленные зависимости `server`). В обоих параметрах укажите один и тот же origin проверяемого сайта:

```powershell
npm run verify:remote -- --server https://SERVICE.onrender.com --origin https://SERVICE.onrender.com
```

Скрипт проверяет валидный HTTPS, Origin, два WSS-соединения и движение. Затем пройдите приёмку с двух компьютеров через интернет для каждой копии. Дополнительная прежняя схема Cloudflare Pages + отдельный Render-сервер сохранена в [DEPLOY.md](docs/DEPLOY.md); её настройки отличаются от текущего `render.yaml`.

## Архитектура и ограничения

Сервер считает движение, столкновения, снаряды, здоровье, перезарядку, счёт и время. Клиент передаёт только направление движения, поворот, прицел и нажатие выстрела с возрастающим номером команды. Сервер проверяет JSON, числовые диапазоны и частоту, ограничивает payload 1 КиБ, отсекает сообщения сверх 60/с, ограничивает подключения и очередь отправки. Симуляция 20 Гц, снимки 10 Гц; Three.js плавно интерполирует их. Точная физика остаётся на сервере.

Процесс один, без кластера, базы и истории матчей; V8 heap ограничен 192 МиБ, WebSocket compression выключена. Origin проверяется по точному списку, без wildcard. Это фильтр браузерных подключений, а не аутентификация: небраузерный клиент способен подставить Origin. Коды комнат являются приглашениями, не секретными паролями.

Никаких токенов инфраструктуры в приложении нет. `VITE_SERVER_URL` — публичная настройка, встроенная в JS: `/ws` для своего сайта либо полный WSS-адрес отдельного сервера. Не кладите секреты в `VITE_*`, клиент или Git. `.env*` исключены из репозитория, кроме безопасных `.env.example`. Токен восстановления отдельного игрока существует только в памяти вкладки и сервера.

Free рассчитан на небольшой тест с друзьями. Сервер может спать, медленно просыпаться и останавливаться при исчерпании лимитов; 512 МБ не гарантируют игровую производительность при любой нагрузке. Число бесплатных часов и объём трафика общие с другими сервисами аккаунта. Нельзя обещать 24/7 без ограничений или нулевые расходы за пределами Free — поэтому способ оплаты не подключается.
