# Два отдельных сайта: Render Free и Enzonic Free

Цель — две независимые копии «Танкового фронта». У каждой свой сайт, WebSocket-сервер, комнаты и матчи. Игроки с Render и Enzonic не встречаются друг с другом: для общего боя нужно открыть одну и ту же копию и воспользоваться приглашением.

```text
GitHub: https://github.com/tanks-online/tank-front
  ├─ https://tank-front.onrender.com
  │    Render Free: сайт + /health + игровой сервер /ws
  └─ https://tank-front-enzonic.mgladkov669.workers.dev
       Cloudflare Workers Free: только HTTPS/WSS-шлюз
           → http://sgp-two.enzonic.com:25610
             Enzonic Free: сайт, файлы, комнаты и игровой сервер
```

В каждой копии один Node.js-процесс отдаёт собранный клиент и обслуживает игру. Cloudflare у Enzonic используется только как входной шлюз: игровая логика, файлы и комнаты остаются на Enzonic. Собственный домен не нужен.

**Статус на 17 октября 2026 года:** [Render-сайт](https://tank-front.onrender.com) развёрнут на Free 512 МБ; проверены настоящий HTTPS/WSS, движение двух автоматических клиентов и отображение 3D-игры в браузере. [Enzonic-сайт через Worker](https://tank-front-enzonic.mgladkov669.workers.dev) тоже доступен: автоматическая проверка HTTPS, точного Origin, WSS, двух игроков и движения прошла на настоящем сервере Enzonic. Его браузерная 3D-проверка тоже пройдена. [Исходный репозиторий](https://github.com/tanks-online/tank-front) загружен, CI прошёл. Карты, платные услуги и пробные платные тарифы не подключались.

Приёмка двумя физическими компьютерами через интернет **не проведена** ни для одной копии. Публикация не считается полностью завершённой до этой проверки. Актуальный протокол — [ACCEPTANCE.md](ACCEPTANCE.md).

## 1. Подготовка проекта

Используйте Node.js 24 LTS локально и на обоих серверах. В текущей панели Enzonic доступен **Node.js 24 (LTS, Recommended)**. Минимальная версия проекта — 22.14. У клиента и сервера отдельные `package-lock.json`, npm workspaces не используются.

В корне проекта:

```powershell
npm run setup
npm test
npm run build:hosted
```

`build:hosted` собирает сервер в `server/dist` и клиент в `client/dist`. По умолчанию используется публичная настройка `VITE_SERVER_URL=/ws`: браузер подключается к WebSocket на том же домене, где открыт сайт. На HTTPS-странице это автоматически WSS. Адрес конкретного провайдера в клиент зашивать не требуется.

Не загружайте в Git `.env`, `node_modules`, приватные ключи и токены. Исходный репозиторий должен содержать `client`, `server`, `scripts`, корневой `package.json`, `render.yaml` и оба lockfile. Созданные локально `dist` в исходном репозитории не нужны: Render собирает их сам.

Для локальной проверки собранного сайта после `build:hosted`, в PowerShell:

```powershell
$env:STATIC_DIR='../client/dist'
npm start
```

Откройте `http://localhost:3000/`. Не задавайте для этой локальной проверки `NODE_ENV=production` без разрешённого origin. При необходимости завершите сервер Ctrl+C и удалите временную настройку командой `Remove-Item Env:STATIC_DIR`.

## 2. Первая копия — Render Free

[Официальная документация Render](https://render.com/docs/your-first-deploy) описывает бесплатный Web Service. Здесь нужны workspace **Hobby** и compute plan **Free**. Не добавляйте способ оплаты, платный диск, базу данных, дополнительные экземпляры или платные preview environments.

### Ручная настройка

1. В [панели Render](https://dashboard.render.com/) нажмите **New → Web Service**.
2. Подключите репозиторий `tanks-online/tank-front`. Для автоматических обновлений используйте Git Provider; доступ к приватным данным других репозиториев не нужен.
3. Заполните поля:

| Поле | Значение |
| --- | --- |
| Name | Для текущей копии — `tank-front`, адрес `https://tank-front.onrender.com` |
| Runtime / Language | `Node` |
| Branch | `main` |
| Root Directory | **Оставить пустым** — собирается весь проект |
| Build Command | `npm run setup && npm run build:hosted` |
| Start Command | `npm start` |
| Compute / Instance Type | **Free — $0** |
| Health Check Path | `/health` |
| Auto-Deploy | On / On Commit |

4. В Environment задайте:

```dotenv
NODE_VERSION=24
NODE_ENV=production
NPM_CONFIG_INCLUDE=dev
VITE_SERVER_URL=/ws
STATIC_DIR=../client/dist
```

`NPM_CONFIG_INCLUDE=dev` нужен сборке TypeScript. `STATIC_DIR` разрешается относительно рабочей папки сервера: корневой `npm start` запускает npm в `server`. Порт не задавайте вручную: Render передаст `PORT`, сервер слушает `0.0.0.0`.

Для собственной копии на Render вручную задавать `ALLOWED_ORIGINS` и `PUBLIC_URL` не требуется: сервер использует доверенный `RENDER_EXTERNAL_URL`, предоставленный платформой. Если `ALLOWED_ORIGINS` уже задан от прежней схемы Cloudflare, удалите его либо замените точным origin этого сайта Render. Явный список имеет приоритет.

5. Проверьте цену $0 и нажмите **Create Web Service**. Если требуется карта, остановитесь, не выполняйте даже временную авторизацию.
6. Дождитесь **Live**. Текущая копия открывается на [tank-front.onrender.com](https://tank-front.onrender.com), проверка сервера — [/health](https://tank-front.onrender.com/health). При воспроизведении на другом аккаунте используйте адрес, фактически выданный его панелью.

Текущая копия импортирована по публичной Git-ссылке без токена GitHub. Автоматические обновления такого импорта не подтверждены; для обновления используйте **Manual Deploy → Deploy latest commit** после зелёного GitHub Actions. Это перезапустит сервер и удалит текущие комнаты. Для автоматической публикации из Git Provider потребуется ваш вход и разрешение Render на выбранный репозиторий.

### Вариант с Blueprint

Вместо ручного создания можно выбрать **New → Blueprint**, подключить тот же репозиторий и использовать `render.yaml` из корня. Он описывает один бесплатный Web Service со всеми перечисленными настройками. В предварительном списке ресурсов должно быть $0. Не создавайте дубликат, если сервис уже создан вручную. Поле `plan: free` сохраняйте: без явного Free значение по умолчанию для нового сервиса может быть платным. [Спецификация Blueprint](https://render.com/docs/blueprint-spec).

### Бесплатные ограничения Render

Free даёт 512 МБ RAM, 0,1 CPU, 750 часов работы в месяц на workspace. Текущий Hobby включает 5 ГБ исходящего трафика и 500 минут сборки в месяц. Исходящие WebSocket-сообщения расходуют трафик. После 15 минут без входящих запросов/сообщений сервис засыпает; первое подключение после простоя запускает его примерно за минуту. При перезапуске текущие комнаты теряются.

Без способа оплаты исчерпание часов/трафика приостанавливает бесплатные сервисы до следующего месяца; исчерпание минут блокирует новые сборки. Не включайте платные услуги для обхода этих ограничений. [Render Free](https://render.com/docs/free), [ресурсы](https://render.com/docs/compute-plans), [трафик](https://render.com/docs/outbound-bandwidth), [сборки](https://render.com/docs/build-pipeline).

## 3. Вторая копия — Enzonic Free

Регистрация — [panel.enzonic.com/auth/register](https://panel.enzonic.com/auth/register), управление — [panel.enzonic.com](https://panel.enzonic.com/).

[Текущая английская страница Node.js](https://enzonic.com/nodejs) указывает один бесплатный сервер на аккаунт при наличии ресурсов: **512 МБ RAM, 50% CPU, 10 ГБ SSD**, без карты, Node.js 18/20/22, без сна поддерживаемых Node-приложений. Выбирайте **Node.js generic → Free**. Не выбирайте Dirt, Flex, платный custom quota и дополнительные порты: Dirt с 512 МБ тоже является платным тарифом.

Параметры реально выданного серверу Free в текущей панели отличаются от рекламной страницы: **512 МиБ RAM, 100% одного CPU, 1 ГБ диска, Сингапур**, Node.js 24. Ориентируйтесь на показанные при создании квоты; платное увеличение не нужно.

1. Откройте создание сервера и выберите шаблон **Node.js generic**, Node.js **24 LTS**, доступный регион и план **Free / $0**.
2. Скопируйте выданные серверу порт и публичный адрес. У текущей копии это **`sgp-two.enzonic.com:25610`**, порт **`25610`**. По [инструкции Enzonic](https://enzonic.com/g/nodejs-generic) нужно слушать именно назначенный порт. `localhost` и произвольный фиксированный порт снаружи недоступны. На другом сервере цифры будут другими.

Далее используйте один из двух вариантов. Для 512 МБ предпочтителен заранее собранный архив: TypeScript и Vite на сервере не запускаются.

### Вариант А: готовый архив для Enzonic

3. Через web file manager/SFTP загрузите `tank-front-enzonic.tar.gz` из выдачи проекта и распакуйте **в корень приложения**. Не запускайте `.tar.gz` как программу. После распаковки структура должна быть такой:

```text
package.json
package-lock.json
server/index.js
server/…остальные собранные модули.js
public/index.html
public/assets/…
```

4. В корне приложения выполните `npm ci --omit=dev`. В этой сборке устанавливается только рабочая зависимость WebSocket; TypeScript и инструменты клиента не устанавливаются. Не загружайте `node_modules` с Windows в Linux-контейнер.
5. В Environment задайте:

```dotenv
NODE_ENV=production
STATIC_DIR=public
PORT=25610
PUBLIC_URL=https://tank-front-enzonic.mgladkov669.workers.dev
```

Это значения текущего сервера и работающего шлюза. Для повторного размещения подставьте назначенный порт и фактический HTTPS-адрес своего Worker. `PUBLIC_URL` — только HTTPS origin без пути, query и секретов. Вместо него можно задать `ALLOWED_ORIGINS=https://tank-front-enzonic.mgladkov669.workers.dev`. Явный `ALLOWED_ORIGINS` имеет приоритет: удалите старое значение для нативного домена Enzonic или замените его адресом шлюза. Если панель уже передаёт правильный `PORT`, не переопределяйте его. Сервер также поддерживает `SERVER_PORT`, но при одновременном задании выбирает `PORT`.

6. Стартовая команда из корня приложения — `npm start`. В runtime-архиве она запускает `server/index.js` с ограничением V8 heap 192 МиБ. Клиент уже собран с `VITE_SERVER_URL=/ws` и использует текущий адрес сайта. Не смешивайте настройки `STATIC_DIR=public` этой сборки с настройками исходного проекта.

В текущей панели вместо отдельного терминала использована страница **Запуск → Изменить команду**. Фактически сохранена команда:

```sh
export PORT="${SERVER_PORT}" NODE_ENV=production STATIC_DIR=public PUBLIC_URL=https://tank-front-enzonic.mgladkov669.workers.dev ALLOWED_ORIGINS=https://tank-front-enzonic.mgladkov669.workers.dev; npm ci --omit=dev --no-audit --no-fund && exec node --max-old-space-size=192 --env-file-if-exists=.env server/index.js
```

Панель подставляет свой `SERVER_PORT`. Поле **Main File** — `server/index.js`, **User Uploaded Files** включено. После сохранения команды откройте **Консоль → Перезапустить сервер**. Перед повторным размещением замените origin Worker своим. Эта команда установки при каждом старте требует доступности npm registry; рабочие зависимости занимают мало памяти.

### Вариант Б: сборка исходного проекта

Через Git import/clone публичного репозитория либо web file manager/SFTP загрузите полный исходный проект. Для публичного GitHub-репозитория токен не нужен. Сохраните папки `client`, `server`, `scripts` и корневой `package.json`.

Установите `NODE_ENV=production`, `NPM_CONFIG_INCLUDE=dev`, `VITE_SERVER_URL=/ws`, `STATIC_DIR=../client/dist`, назначенный `PORT` и точный HTTPS `PUBLIC_URL`. Выполните в корне `npm run setup`, затем `npm run build:hosted`. После успешной сборки команда запуска из корня — `npm start`. Здесь `NPM_CONFIG_INCLUDE=dev` нужен TypeScript во время сборки.

Если сборка не помещается в 512 МБ, не увеличивайте платные ресурсы: используйте вариант А. У исходного проекта и runtime-архива разные структура папок и стартовые скрипты, поэтому загружайте один выбранный вариант целиком.

### Почему используется бесплатный Cloudflare Worker

У текущей копии проверен нативный бесплатный адрес `tank-front-online.enzonic.dev`: HTTPS завершается **ошибкой соответствия сертификата имени сайта**. Сертификат содержит имя `sgp-two.enzonic.com`, а не `tank-front-online.enzonic.dev`. Исключение безопасности не добавлялось, проверка TLS не отключалась. Такой адрес нельзя объявить готовым защищённым сайтом.

В публичной документации Enzonic бесплатные поддомены упомянуты отдельно от auto-SSL платных custom reverse proxy domains. [Условия Node.js](https://enzonic.com/nodejs), [поддержка WebSockets](https://enzonic.com/web-hosting). Платный прокси/сертификат не подключался. Вместо него подготовлен Worker Free с фиксированным upstream `http://sgp-two.enzonic.com:25610`.

**Граница шифрования:** браузер соединяется с Cloudflare по HTTPS/WSS с проверяемым сертификатом; от Cloudflare до Enzonic запросы идут по **HTTP, а WebSocket — без TLS**. Эта схема не обеспечивает сквозное TLS-шифрование до Enzonic. Она не исправляет сертификат нативного домена. Файлы игры, симуляция, комнаты и игроки при этом находятся на Enzonic, а не в Worker.

### Как воспроизвести Worker Free через браузер

1. Откройте Cloudflare Dashboard → **Workers & Pages → Create application → Worker**. Выберите бесплатный Worker, например **Start with Hello World**. Не выбирайте платный Workers plan и не добавляйте способ оплаты.
2. Задайте имя `tank-front-enzonic`. Cloudflare назначит адрес вида `https://tank-front-enzonic.ВАШ-СУБДОМЕН.workers.dev`. В текущем аккаунте проверенный адрес — `https://tank-front-enzonic.mgladkov669.workers.dev`.
3. Откройте **Edit code**, замените стартовый пример полным содержимым `gateway/worker.js` из репозитория и нажмите **Deploy**. Если у вас другое выделение Enzonic, замените только фиксированную константу `UPSTREAM` на его HTTP-адрес с портом. Конфигурация для Wrangler сохранена в `gateway/wrangler.jsonc`; для ручного способа устанавливать Wrangler не нужно.
4. Код разрешает GET/HEAD/OPTIONS и WebSocket Upgrade только для `/ws`, удаляет Cookie/Authorization и сохраняет браузерный Origin. Адрес назначения фиксирован в коде: нельзя добавлять выбор чужого upstream через параметры ссылки.
5. В Enzonic задайте `PUBLIC_URL` равным точному HTTPS origin своего Worker. Если существует `ALLOWED_ORIGINS`, замените его тем же origin либо удалите, чтобы использовался `PUBLIC_URL`. Перезапустите Node-сервер.
6. Откройте адрес Worker и его `/health`. Затем выполните удалённую проверку ниже и проверьте 3D-игру в браузере. Ошибка на любом шаге означает, что шлюз ещё не принят.

Workers Free предоставляет **100 000 запросов в сутки на аккаунт**, сброс в 00:00 UTC (03:00 по Москве). Начальный WebSocket Upgrade считается одним запросом; проходящие через обычный Worker WebSocket-сообщения не считаются отдельными запросами. Загрузка HTML/JS/CSS и `/health` расходует запросы; новые подключения после обрыва тоже. При исчерпании бесплатной квоты возможен Error 1027 — дождитесь сброса, не повышайте тариф. Durable Objects здесь не используются. [Лимиты](https://developers.cloudflare.com/workers/platform/limits/), [учёт WebSocket-запросов](https://developers.cloudflare.com/workers/platform/pricing/).

**Текущий Worker прошёл проверку HTTPS/WSS, точного Origin, двух игровых соединений и движения.** При повторном размещении пройдите её заново. Не обходите ошибки сертификатов и не подключайте платные услуги ради объявления готовности. Браузерная проверка Enzonic тоже пройдена. Физическая приёмка двумя друзьями пока остаётся незавершённой.

## 4. Проверка каждой копии

Проверяйте Render и Enzonic через шлюз отдельно. Для текущих адресов:

```powershell
npm run verify:remote -- --server https://tank-front.onrender.com --origin https://tank-front.onrender.com
npm run verify:remote -- --server https://tank-front-enzonic.mgladkov669.workers.dev --origin https://tank-front-enzonic.mgladkov669.workers.dev
```

Команды выполняются локально из корня проекта после `npm run setup`. Они проверяют HTTPS, точный Origin, `/health`, `/rooms`, два WSS-подключения `/ws` и движение. **Обе текущие копии прошли эту техническую проверку.** Успешная проверка протокола ещё не доказывает, что оба физических устройства играют через интернет.

Добавьте `--full` к каждой команде для полного автоматического трёхминутного матча: оба временных клиента перемещаются обычными командами, проверяют выстрелы, урон, уничтожение, возрождение, одинаковые результаты и запуск нового раунда. Чужой Origin должен получить отказ WSS 403. Проверочные подключения закрываются по окончании. Эта проверка расходует небольшой объём бесплатного трафика.

**17 октября 2026 года оба публичных прогона `--full` завершились PASS FULL и кодом 0.** У Render проверочная комната была `G2X5ED`, у Enzonic — `X8RXR3`; они закрыты и не являются действующими приглашениями. Проверка чужого Origin тоже прошла на обоих адресах.

Для каждой копии выполните [ACCEPTANCE.md](ACCEPTANCE.md) с **двух компьютеров с клавиатурой и мышью**, желательно через разные сети. Один компьютер может использовать мобильную точку доступа. Оба игрока открывают один и тот же сайт, вводят разные ники и нажимают «Играть». Ссылка «Пригласить» обеспечивает вход друга в ту же комнату. Подтвердите движение, выстрелы, попадания, результат матча и восстановление после краткого разрыва связи. Сенсорного управления нет.

Запишите реальные URL, коммит, время с часовым поясом, устройства, сети и результат отдельно для каждого провайдера. Убедитесь, что нигде не добавлена карта и всё ещё выбраны бесплатные планы. Только после этих проверок можно считать соответствующую копию опубликованной полностью.

## 5. Важные ошибки настройки

| Признак | Что проверить |
| --- | --- |
| На Render доступен `/health`, но нет игры | Root Directory должен быть пустым; build — обе папки; `STATIC_DIR=../client/dist`; start из корня — `npm start`. |
| `tsc` не найден | `NPM_CONFIG_INCLUDE=dev` во время сборки, оба lockfile на месте. |
| Игра подключается к другому провайдеру | Сборка клиента должна использовать `VITE_SERVER_URL=/ws`. После изменения нужна новая сборка. |
| Origin запрещён | Render использует свой `RENDER_EXTERNAL_URL`; Enzonic должен разрешать точный origin Worker через `PUBLIC_URL` либо приоритетный `ALLOWED_ORIGINS`. |
| Enzonic не отвечает | Проверьте `0.0.0.0`, назначенный `PORT`, правильную стартовую папку и лог процесса. |
| Ошибка сертификата `tank-front-online.enzonic.dev` | Не обходите TLS-проверку. Используйте Worker после его успешной проверки; нативный сертификат Enzonic сейчас не соответствует этому имени. |
| Worker возвращает 503 | Проверьте, запущен ли Enzonic и доступен ли его `/health` на назначенном порту. Worker не запускает Node-процесс вместо Enzonic. |
| Worker возвращает Error 1027 | Исчерпана бесплатная суточная квота. Дождитесь её сброса, не включайте платный план. |
| Друг не попал в тот же бой | Проверьте, что открыт тот же провайдер, и используйте ссылку приглашения. Комнаты двух копий независимы. |
| Сервер перезапустился | Комнаты в памяти утрачены. Вернитесь в меню, нажмите «Играть» и отправьте новое приглашение. |

Проверенные сведения о тарифах относятся к 17 октября 2026 года. Бесплатные планы имеют ограничения доступности и производительности; эта схема предназначена для небольших матчей с друзьями.
