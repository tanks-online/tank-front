# Бесплатная публикация на Render

Основной сайт: **[https://tank-front.onrender.com/](https://tank-front.onrender.com/)**. Исходники: [tanks-online/tank-front](https://github.com/tanks-online/tank-front). Сайт и Node.js-сервер работают на одном Render Web Service Free; WebSocket подключается к `/ws` того же сайта. Enzonic, Cloudflare и отдельный домен не нужны.

Выпуск **«Телефон + ПК» опубликован на Render 24 октября 2026 года**. Прошли 28 серверных и 18 клиентских тестов, TypeScript, сборка и GitHub Actions. На публичном сайте проверены общий бой двух режимов, HTTPS/WSS и полный матч двух автоматических клиентов. Enzonic остановлен. Для окончательной приёмки нужен совместный бой на физическом телефоне и ПК; [актуальный протокол](ACCEPTANCE.md).

## Бесплатный тариф и ограничения

При первоначальном размещении 17 октября 2026 года использовались workspace **Hobby** и instance **Free**, без карты и платных услуг. Free предоставлял 512 МБ RAM / 0,1 CPU, сон после 15 минут простоя и 750 бесплатных часов в месяц на workspace. Тогда Hobby включал 5 ГБ исходящего трафика и 500 минут сборки в месяц. Это зафиксированные на ту дату условия: **перед созданием или изменением сервиса проверьте текущие значения в панели**, не воспринимайте их как неизменную квоту.

Render поддерживает управляемый HTTPS и WSS. После сна первый вход обычно занимает около минуты; игра сообщает о запуске сервера. WebSocket-трафик расходует исходящую квоту. Часы, трафик и минуты сборки общие с другими сервисами workspace. Без способа оплаты исчерпание квот может приостановить сервисы или новые сборки; повышение тарифа для этого проекта не допускается.

Не подключайте карту, платные диски, базы, дополнительные экземпляры и платные планы. Если панель требует карту для Free, остановитесь: не подтверждайте оплату. Сон, deploy и перезапуск теряют комнаты и результаты текущего матча, поскольку они хранятся в памяти.

Официальные страницы для проверки условий: [Render Free](https://render.com/docs/free), [compute plans](https://render.com/docs/compute-plans), [исходящий трафик](https://render.com/docs/outbound-bandwidth), [сборки](https://render.com/docs/build-pipeline), [WebSocket](https://render.com/docs/websocket).

## 1. Загрузить исходники на GitHub

Для уже созданного проекта используйте [существующий репозиторий](https://github.com/tanks-online/tank-front). Для собственной копии войдите на [GitHub](https://github.com/), нажмите **New repository**, создайте публичный репозиторий без секретов и загрузите содержимое проекта. В корне должны лежать `package.json`, `render.yaml` и папки `client`, `server`, `scripts`, `.github` — не дополнительная внешняя папка.

Загрузите оба `package-lock.json`. Не загружайте `node_modules`, `.env`, `.env.local` и токены. В **Actions** дождитесь успешного **Check game**. GitHub Actions проверяет тесты и сборку; публикацию существующего Render-сервиса выполняйте следующим шагом.

## 2. Создать Render Web Service

Войдите на [Render](https://dashboard.render.com/). Выберите **New → Web Service → Public Git Repository** и вставьте:

```text
https://github.com/tanks-online/tank-front
```

Для собственной копии укажите свой URL. Публичному импорту не нужен GitHub-токен. Заполните:

| Поле | Значение |
| --- | --- |
| Name | `tank-front` или свободное имя |
| Language / Runtime | `Node` |
| Branch | `main` |
| Root Directory | оставить пустым |
| Build Command | `npm run setup && npm run build:hosted` |
| Start Command | `npm start` |
| Instance Type | **Free**, цена 0 |
| Health Check Path | `/health` |

Добавьте Environment Variables:

```dotenv
NODE_VERSION=24
NODE_ENV=production
NPM_CONFIG_INCLUDE=dev
VITE_SERVER_URL=/ws
STATIC_DIR=../client/dist
```

`NPM_CONFIG_INCLUDE=dev` позволяет установить TypeScript и Vite для сборки. `STATIC_DIR` разрешается относительно папки `server`, в которой запускается Node. `VITE_SERVER_URL=/ws` встраивается в клиент при сборке и автоматически использует WSS на публичном HTTPS-сайте.

**Не задавайте `PORT` вручную.** Render назначает порт; приложение слушает его на `0.0.0.0`. Также не переопределяйте `RENDER_EXTERNAL_URL`: сервер использует управляемый адрес Render как разрешённый Origin. Для этой схемы отдельные `PUBLIC_URL` и `ALLOWED_ORIGINS` не нужны; удалите старые значения других хостингов, если они были добавлены.

Проверьте **Free**, отсутствие платных дополнений и способа оплаты, затем нажмите **Create Web Service**. Дождитесь состояния **Live**. Render выдаст HTTPS-адрес вида `https://ИМЯ.onrender.com`. Откройте его и `/health`; последний должен вернуть JSON с `ok: true`.

## 3. Обновлять существующую игру

1. Загрузите изменённые исходники в тот же GitHub-репозиторий и ветку `main`.
2. В GitHub **Actions** дождитесь успешного **Check game** для нового коммита.
3. В Render откройте существующий **tank-front** → **Manual Deploy → Deploy latest commit**. При публичном Git-импорте без подключения GitHub-провайдера не полагайтесь на автоматический deploy.
4. Дождитесь **Live** и проверьте, что в deploy указан нужный коммит. Обновляйте клиент и сервер вместе: они используют общий протокол.
5. Перезагрузите сайт и выполните проверки ниже. Предупредите друзей, что deploy прерывает текущие матчи, и отправьте новое приглашение после входа.

Для обычного обновления не создавайте второй сервис и не меняйте Free на платный план. Автоматические GitHub Actions выполняют проверку кода; сервер запускает Render.

## 4. Проверить публикацию

Локально в корне проекта после `npm run setup` выполните:

```powershell
npm run verify:remote -- --server https://tank-front.onrender.com --origin https://tank-front.onrender.com --directional
```

Оба параметра — один точный HTTPS origin без завершающего `/`. Для собственной копии замените адрес. Проверка использует валидный TLS, `/health`, `/rooms`, точный Origin, два WSS-подключения и направление движения. Чужой Origin должен получить отказ WSS 403. Не отключайте проверку сертификата.

Для полного трёхминутного матча:

```powershell
npm run verify:remote -- --server https://tank-front.onrender.com --origin https://tank-front.onrender.com --directional --full
```

Автоматические клиенты проверяют стрельбу, урон, уничтожение, возрождение, общий результат и повторный бой. Они проверяют серверный протокол, но не доказывают удобство сенсорного управления. После deploy выполните проверку на **физическом телефоне и ПК**, желательно через разные сети:

1. На ПК откройте сайт, выберите **«ПК»**, введите ник и нажмите «Играть». Отправьте приглашение на телефон.
2. На телефоне откройте приглашение, выберите **«Телефон»**, введите другой ник и войдите. Выбор устройства предлагается при каждом входе; изменить его можно в настройках. Убедитесь, что оба игрока видны в одной комнате и матч начался.
3. Двигайтесь левым стиком, удерживайте правый для прицеливания и автоматического огня. Проверьте одновременную работу двух пальцев и индикатор перезарядки. Низкое качество на телефоне включается по умолчанию; качество ПК хранится отдельно.
4. Проверьте телефон в альбомном и портретном положении. Нативный полный экран и блокировка ориентации включаются там, где браузер их поддерживает. Иначе при портретном экране интерфейс разворачивается на 90° средствами CSS; оба стика должны продолжать работать правильно.
5. На ПК проверьте WASD/стрелки, мышь, ЛКМ/пробел, Shift и масштаб. Попадания, уменьшение HP, возрождение, счёт и результат полного матча должны совпадать на двух устройствах.
6. Проверьте повторный бой, краткий обрыв связи и восстановление. Запишите устройства, браузеры, сети, коммит и результат в [ACCEPTANCE.md](ACCEPTANCE.md).

Локальная браузерная проверка охватила 667 × 375, 844 × 390 и 390 × 844, общий бой режимов «Телефон» и «ПК», движение, огонь и перезарядку без ошибок консоли. Она не заменяет перечисленные шаги на настоящем телефоне через интернет.

## 5. Что требует вашего входа

- GitHub: загрузка исходников в ваш репозиторий и просмотр Actions.
- Render: создание/настройка Free-сервиса и запуск deploy.
- Телефон и ПК: совместный бой через интернет с проверкой обоих видов управления и связи.

Пароли и токены не нужно присылать в чат или записывать в репозиторий. `VITE_*` доступны всем посетителям сайта; секреты туда не помещают.

## Частые ошибки

| Признак | Исправление |
| --- | --- |
| Есть `/health`, но нет игры | Root пустой, build собирает обе папки, `STATIC_DIR=../client/dist`, start — `npm start` из корня. |
| `tsc` или `vite` не найдены | Проверьте `NPM_CONFIG_INCLUDE=dev` и оба lockfile. |
| Ошибка Origin | Уберите старые `ALLOWED_ORIGINS`/`PUBLIC_URL`; используйте управляемый `RENDER_EXTERNAL_URL`. |
| Игра соединяется со старым сервером | `VITE_SERVER_URL=/ws`, затем новая сборка и deploy. |
| Долго подключается после простоя | Дождитесь пробуждения Render; не ставьте внешний постоянный опрос для обхода сна. |
| Матч исчез после deploy | Память сервера сброшена: вернитесь в меню, войдите снова и отправьте новое приглашение. |
| Друг попал в другую комнату | Отправьте ссылку через «Пригласить», оба откройте Render-сайт. |
| Достигнута квота Free | Дождитесь сброса или остановите сервис. Не подключайте оплату и повышение тарифа. |
