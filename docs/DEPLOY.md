# Публикация Tank Front: Cloudflare Pages Free + Render Free

> Это дополнительная инструкция для прежней схемы с отдельным клиентом на Cloudflare Pages и сервером Render. Текущая основная схема — **два независимых сайта на Render Free и Enzonic Free**, каждый со своим сервером: [TWO-HOSTS.md](TWO-HOSTS.md). Для неё используйте актуальный `render.yaml` из корня и настройки из новой инструкции; конфигурация Render ниже относится только к отдельному серверу.

Статус этого руководства: **проект подготовлен к размещению; публичные адреса и игра с двух физических устройств ещё не подтверждены**. Наличие файлов и успешная локальная сборка не означают, что публикация завершена.

Схема размещения:

```text
GitHub: один репозиторий
├── client/  → Cloudflare Pages → https://PROJECT.pages.dev
└── server/  → Render Free      → https://SERVICE.onrender.com
                                wss://SERVICE.onrender.com/ws
```

Клиент — статические HTML, CSS и JavaScript после сборки Vite. Сервер — отдельный постоянный процесс Node.js с WebSocket. Игра рассчитана на настоящих игроков; ботов нет. Собственный домен, база данных и платные дополнения для этой схемы не нужны.

## 1. Условия бесплатного размещения

Сведения проверены **17 октября 2026 года**. Перед созданием сервиса ещё раз посмотрите стоимость в его форме: тарифы и правила могут измениться.

| Что | Бесплатные условия и ограничения |
| --- | --- |
| Cloudflare Pages | Бесплатный адрес `PROJECT.pages.dev`, SSL, статическая раздача без счётчика исходящего трафика. Free: 500 сборок в месяц, одна одновременно, до 20 минут на сборку, 20 000 файлов, максимум 25 MiB на файл. |
| Render Web Service | План **Free**: 512 МБ RAM и 0,1 CPU. Бесплатный адрес `SERVICE.onrender.com`, управляемый TLS и публичные WSS-подключения. |
| Render: простой | После 15 минут без входящих HTTP-запросов или WebSocket-сообщений сервис засыпает. Следующий запрос или новое WebSocket-подключение запускает его примерно за минуту. Во время реальной игры сообщения игроков считаются активностью. |
| Render: месячные квоты | 750 часов работы Free на весь workspace за календарный месяц. Текущий Hobby включает 5 ГБ исходящего трафика и 500 минут сборки в месяц. Ответы WebSocket расходуют исходящий трафик. Квоты общие с другими сервисами workspace. |
| Render: исчерпание квот без карты | При исчерпании часов или трафика бесплатные сервисы приостанавливаются до следующего месяца. При исчерпании минут блокируются новые сборки, а существующая версия продолжает работать. |
| Данные игры | Комнаты и текущий матч хранятся в памяти. Перезапуск, новый deploy или сон сервера завершают матчи; постоянного хранения нет. |

Официальные источники: [Cloudflare Pages: бесплатное начало и SSL](https://www.cloudflare.com/products/pages/), [лимиты Pages Free](https://developers.cloudflare.com/pages/platform/limits/), [Render Free](https://render.com/docs/free), [ресурсы Render Free](https://render.com/docs/compute-plans), [исходящий трафик](https://render.com/docs/outbound-bandwidth), [минуты сборки](https://render.com/docs/build-pipeline), [WSS на Render](https://render.com/docs/websocket).

**Правило для этой публикации: нигде не добавляйте карту и не выбирайте платный тариф.** На Render нужны бесплатный workspace Hobby и отдельный compute plan Free для самого сервера. Это разные настройки. Не создавайте платные диски, базы, workers, cron jobs и дополнительные экземпляры. Не включайте платные preview environments и не покупайте дополнительные квоты.

Cloudflare прямо указывает бесплатное начало без карты. [Официальная статья Render](https://render.com/articles/platforms-with-a-real-free-tier-for-developers-in-2026) также описывает запуск без карты. Однако конкретная регистрация может потребовать дополнительной проверки аккаунта: [ответ поддержки Render](https://community.render.com/t/the-deployement-of-a-web-service-fails/36005). Если форма требует карту, **остановитесь на этом экране**. Такая регистрация не удовлетворяет условию проекта; не выполняйте даже временную авторизацию карты. Успешная регистрация без карты должна быть подтверждена вашим аккаунтом, а не обещанием этого руководства.

Не ставьте внешние «будильники», которые бесконечно опрашивают сервер ради обхода сна. Первый вход после простоя просто займёт дольше. При достижении бесплатных лимитов остановитесь и дождитесь их обновления.

## 2. Подготовьте аккаунты и локальную папку

Понадобятся бесплатные аккаунты [GitHub](https://github.com/signup), [Cloudflare](https://dash.cloudflare.com/sign-up) и [Render](https://dashboard.render.com/register). Установите Git и Node.js **24 LTS**; также подойдёт актуальная версия Node.js 22, начиная с 22.14. Проверьте в терминале:

```powershell
node --version
npm --version
git --version
```

Распакуйте проект в отдельную папку `tank-front`. Все следующие команды выполняйте из неё, где рядом лежат `client`, `server`, `package.json` и `render.yaml`.

У клиента и сервера отдельные `package.json` и `package-lock.json`. Корневые команды только запускают команды подпапок; npm workspaces не используются.

```powershell
npm --prefix client ci
npm --prefix server ci
```

Если Windows не разрешает запуск `npm.ps1`, используйте `npm.cmd` в этих командах. Не меняйте системную политику выполнения ради проекта.

Для локальной разработки создайте `client/.env.local`:

```dotenv
VITE_SERVER_URL=ws://localhost:3000/ws
```

И `server/.env`:

```dotenv
PORT=3000
ALLOWED_ORIGINS=http://localhost:5173
```

Теперь проверьте сборку и серверные тесты:

```powershell
npm --prefix client run build
npm --prefix server run build
npm --prefix server test
```

Настройку клиента нужно создать **до** сборки: без `VITE_SERVER_URL` сборка намеренно останавливается. Локальный `ws://localhost:3000/ws` допустим для проверки на этом компьютере. При публикации Cloudflare подставит отдельное production-значение `wss://SERVICE.onrender.com/ws` из своего окружения.

В двух терминалах запустите:

```powershell
npm --prefix server run dev
```

```powershell
npm --prefix client run dev
```

Откройте адрес Vite из терминала. Сервер разработки нужен только локально; в Cloudflare будет опубликована папка `client/dist`.

В главном меню введите ник и нажмите **«Играть»**. Сервер сам подберёт свободную комнату или создаст новую; бой начнётся, когда подключатся хотя бы два человека. Танк, звук и качество меняются в настройках. Для входа друга в ту же комнату скопируйте приглашение в игре и отправьте полученную ссылку.

## 3. Загрузите один репозиторий на GitHub

1. В GitHub нажмите **New repository**. Например, назовите его `tank-front`.
2. Выберите **Public** для простого бесплатного подключения. На экране создания не добавляйте README, license и gitignore: они уже находятся в проекте.
3. Нажмите **Create repository** и скопируйте HTTPS-адрес репозитория.
4. В локальной папке проекта выполните команды, заменив `USERNAME` своим именем GitHub:

```powershell
git init -b main
git add .
git status --short
```

Перед коммитом проверьте список. В нём должны быть оба lockfile и исходники; не должно быть `.env`, `.env.local`, `node_modules`, приватных ключей и файлов с токенами. `.env.example` — безопасные образцы, их можно публиковать.

```powershell
git commit -m "Prepare Tank Front client and server"
git remote add origin https://github.com/USERNAME/tank-front.git
git push -u origin main
```

GitHub может открыть вход в браузере. Пароль или токен не вставляйте в адрес `origin` и не сохраняйте в файлах проекта. Если Git сообщает, что репозиторий уже существует локально, не повторяйте `git init`: используйте его существующую историю и проверьте `git remote -v`.

После push на GitHub в корне должны отображаться папки `client`, `server` и файл `render.yaml`. Для этой схемы GitHub хранит исходники; публикацией клиента управляет интеграция Cloudflare Pages.

## 4. Запустите сервер на Render Free

Сначала выберите короткое имя для будущего сайта Cloudflare, например `my-tank-front`. Его ожидаемый production origin — `https://my-tank-front.pages.dev`. Если имя окажется занято, позже исправьте адрес на реально выданный.

1. Войдите в Render. Оставьте workspace на **Hobby**, без способа оплаты.
2. Нажмите **New → Web Service**.
3. Подключите GitHub и дайте доступ только к репозиторию игры. Выберите его.
4. Заполните поля:

| Поле Render | Значение |
| --- | --- |
| Name | Например, `my-tank-front-server`; итоговый URL смотрите в панели |
| Branch | `main` |
| Runtime / Language | `Node` |
| Root Directory | `server` |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm start` |
| Compute / Instance Type | **Free — $0** |
| Health Check Path | `/health` |
| Auto-Deploy | On, для ветки `main` |

5. В **Environment** добавьте:

| Имя | Значение |
| --- | --- |
| `NODE_VERSION` | `24` |
| `NODE_ENV` | `production` |
| `NPM_CONFIG_INCLUDE` | `dev` — для установки TypeScript перед сборкой |
| `ALLOWED_ORIGINS` | `https://my-tank-front.pages.dev` — без завершающего `/` |

`PORT` вручную не добавляйте: Render передаёт его автоматически, обычно это `10000`. Сервер читает `process.env.PORT` и слушает `0.0.0.0`. HTTP и WebSocket идут через один процесс и порт. Во внешнем URL порт писать не нужно. TLS завершается на стороне Render; сертификат и HTTPS внутри процесса Node.js настраивать не требуется. [Официальная настройка порта и TLS](https://render.com/docs/web-services#port-binding).

6. Убедитесь, что цена равна нулю и выбран Free. Нажмите **Create Web Service**. Если появляется обязательная карта, не продолжайте.
7. Дождитесь состояния **Live**. Откройте `https://SERVICE.onrender.com/health`, подставив настоящий адрес из панели. Должен вернуться JSON, а не страница ошибки.
8. Сохраните оба адреса:

```text
Проверка сервера: https://SERVICE.onrender.com/health
Адрес для клиента: wss://SERVICE.onrender.com/ws
```

Если сервер спал, первый запрос может занять около минуты. Дождитесь ответа и повторите проверку. Не соглашайтесь на Upgrade ради устранения этой задержки.

### Вариант с render.yaml

Текущий `render.yaml` из репозитория собирает **сайт и сервер вместе** из корня проекта для новой схемы [TWO-HOSTS.md](TWO-HOSTS.md). Он не соответствует ручным настройкам отдельного сервера из раздела 4 этой дополнительной инструкции. Для схемы Cloudflare + отдельный Render-сервер используйте ручное создание выше; для Blueprint переходите к основной инструкции. В обоих случаях сохраняйте `plan: free`: по [спецификации Render Blueprint](https://render.com/docs/blueprint-spec) значение по умолчанию для нового Web Service может быть платным.

### Если Render требует карту: резервный вариант Bonto Free

Не вводите карту в Render. В качестве отдельного варианта рассмотрите [Bonto Free](https://bonto.dev/pricing): провайдер прямо указывает **Free forever**, отсутствие требования карты, Node.js, постоянные процессы, WebSockets для multiplayer и автоматический HTTPS на `APP.bonto.run`. Это подтверждение опубликованных условий; запуск этой игры на конкретном аккаунте Bonto и её WSS-адрес ещё требуют проверки. [Описание backend-хостинга](https://bonto.dev/best/free-backend-hosting).

В [таблице тарифов Bonto](https://bonto.dev/docs/pricing-plans) Free включает 75 часов в месяц, 512 МБ RAM, 0,5 CPU и 256 МБ места, без always-on. В одном FAQ страницы pricing остаётся число 50 часов: проверьте квоту, показанную вашим кабинетом, и до её подтверждения рассчитывайте на меньшее значение. Часы общие для приложений; редактор также может расходовать квоту. При исчерпании приложение приостанавливается, а не переходит на платный тариф. После 30 минут неактивности оно засыпает; обычное пробуждение занимает 3–10 секунд. [Сон и WebSocket-активность](https://bonto.dev/docs/auto-sleep-and-wake), [учёт часов](https://bonto.dev/docs/usage-hours).

Для ручного переноса сервера без Docker:

1. [Зарегистрируйтесь в Bonto](https://bonto.dev/docs/creating-your-account), подтвердите email и оставьте индивидуальный тариф **Free**. Если форма всё же требует карту или оплату, остановитесь.
2. Нажмите **New App** и задайте имя. В панели пакетов выберите **Node.js 22**, убедитесь в терминале `node --version`, что версия не ниже 22.14. По умолчанию Bonto может выбирать Node.js 20. [Выбор runtime](https://bonto.dev/docs/node-versions).
3. Локально из корня игры выполните `npm --prefix server ci` и `npm --prefix server run build`.
4. Через редактор файлов Bonto перенесите **содержимое** `server/dist`, сохранив папку `dist`, а также `server/package.json` и `server/package-lock.json` в корень приложения Bonto. Должно получиться `package.json`, `package-lock.json`, `dist/index.js` и остальные собранные модули. `.env`, `node_modules` и токены не загружайте. Основной исходный репозиторий с `client` и `server` остаётся на GitHub.
5. В **Environment** задайте `NODE_ENV=production` и `ALLOWED_ORIGINS=https://PROJECT.pages.dev`. Автоматический `PORT` оставьте площадке. [Переменные Bonto](https://bonto.dev/docs/environment-variables).
6. В терминале приложения выполните `npm ci --omit=dev`, затем используйте стартовый скрипт `npm start` из загруженного `package.json`. После установки/изменения файлов перезапустите приложение через его панель. TypeScript уже скомпилирован локально; здесь запускаются файлы `dist`.
7. Откройте `https://APP.bonto.run/health`. Затем в Cloudflare задайте `VITE_SERVER_URL=wss://APP.bonto.run/ws` и пересоберите клиент.
8. Выполните `npm run verify:remote -- --server https://APP.bonto.run --origin https://PROJECT.pages.dev`. Проверка должна подтвердить настоящий HTTPS, WSS, Origin и игровые сообщения. После этого пройдите ту же приёмку с двух физических устройств из раздела 7, записав адрес Bonto вместо Render.

Не включайте платный Always-On, платный тариф и дополнительные ресурсы. При достижении бесплатной квоты дождитесь её обновления. [Официальный quickstart Bonto](https://bonto.dev/docs/quickstart) описывает приложение, автоматический `PORT` и публичный URL. Вариант Bonto здесь подготовлен как инструкция по переносу; он **не считается уже развёрнутым или проверенным**.

## 5. Опубликуйте клиент в Cloudflare Pages Free

1. Войдите в Cloudflare, откройте **Workers & Pages**.
2. Выберите **Create application → Pages → Connect to Git**. В некоторых версиях панели сначала отображается вкладка Pages. Создайте именно проект Pages с Git integration.
3. Подключите GitHub и разрешите доступ к репозиторию игры. Выберите его и нажмите **Begin setup**.
4. Укажите настройки:

| Поле Cloudflare Pages | Значение |
| --- | --- |
| Project name | Например, `my-tank-front` |
| Production branch | `main` |
| Framework preset | `None` |
| Root directory | `client` |
| Build command | `npm ci && npm run build` |
| Build output directory | `dist` — относительно `client` |

5. В **Environment variables** для окружения **Production** добавьте:

```dotenv
NODE_VERSION=24
VITE_SERVER_URL=wss://SERVICE.onrender.com/ws
```

Вставьте реальный hostname Render, полностью сохранив `wss://` и `/ws`. Не используйте здесь `localhost`, `http://`, `https://`, внутренний адрес Render или номер порта.

6. Нажмите **Save and Deploy**, дождитесь успешной сборки и откройте production URL `https://PROJECT.pages.dev` из панели.
7. Для бесплатного размещения используйте этот адрес. Покупать домен, добавлять зону DNS или подключать платные Workers/Functions не требуется.

Pages сам выпускает сертификат для `pages.dev`. Ресурсы клиента собираются для корня сайта; на Pages не нужен префикс имени GitHub-репозитория. Файлы результата — обычная статика. [Интеграция с Git](https://developers.cloudflare.com/pages/get-started/git-integration/) и [настройка сборки](https://developers.cloudflare.com/pages/configuration/build-configuration/).

`VITE_SERVER_URL` — **публичная настройка**, которая встраивается в JavaScript при сборке. Каждый посетитель может её увидеть. Изменение переменной в панели Cloudflare требует новой сборки: откройте Deployments и повторите deployment либо отправьте новый коммит. Простого обновления вкладки недостаточно. Любые пароли и секретные токены запрещено помещать в переменные `VITE_*`. [Официальное описание Vite](https://vite.dev/guide/env-and-mode).

## 6. Свяжите реальные адреса и ограничьте Origin

После выдачи адреса Cloudflare откройте **Render → ваш сервис → Environment** и установите:

```dotenv
ALLOWED_ORIGINS=https://PROJECT.pages.dev
```

Это только origin: схема + hostname, без пути и завершающего слеша. Пример: `https://my-tank-front.pages.dev`. Сохраните изменение с перезапуском или redeploy. Проверьте, что на Cloudflare значение клиента соответствует именно этому серверу:

```dotenv
VITE_SERVER_URL=wss://SERVICE.onrender.com/ws
```

Сервер проверяет разрешённый origin для запросов сайта и WebSocket handshake. Не ставьте `*`, `https://*.pages.dev` и не отключайте проверку, чтобы «всё заработало». Для production оставляйте только production origin.

Preview-сборки Cloudflare имеют другие адреса и по умолчанию не должны подключаться к рабочему серверу. Если нужно проверить конкретную preview-сборку, вручную добавьте её **полный точный origin** через запятую:

```dotenv
ALLOWED_ORIGINS=https://PROJECT.pages.dev,https://EXACT-PREVIEW.PROJECT.pages.dev
```

После проверки удалите preview origin. Не разрешайте все поддомены Cloudflare. Публичный адрес сервера не является секретом; Origin-проверка ограничивает браузерные подключения, но не заменяет аутентификацию пользователей.

## 7. Проверьте HTTPS, WSS и игровую связь

Сначала убедитесь, что `https://PROJECT.pages.dev` и `https://SERVICE.onrender.com/health` открываются без предупреждений сертификата. Не обходите ошибки TLS.

Из корня локального проекта запустите проверку удалённого сервера, подставив настоящие адреса:

```powershell
npm run verify:remote -- --server https://SERVICE.onrender.com --origin https://PROJECT.pages.dev
```

Она проверяет `/health`, `/rooms` и WebSocket `/ws` с указанным Origin. Сначала разбудите спящий сервис через `/health`, если проверка не дождалась ответа. Ожидается успешный результат и код завершения 0. Ошибка означает, что публикация ещё не прошла приёмку.

Автоматическая проверка протокола не подтверждает доступность на втором устройстве, удобство управления и совместную игру через интернет.

### Обязательная приёмка двумя настоящими игроками

Используйте два компьютера с клавиатурой и мышью, желательно через разные сети: например, первый через домашнюю сеть, второй через мобильную точку доступа. Обеим сторонам отправьте **production-ссылку Cloudflare Pages**. Сенсорное управление в этой версии не реализовано.

- [ ] Оба устройства открывают один и тот же production URL по HTTPS без ошибок сертификата.
- [ ] В главном меню видны ник и «Играть»; выбор танка, звук и качество доступны в настройках.
- [ ] Первый игрок вводит ник и нажимает «Играть»: сервер автоматически находит или создаёт комнату, подключение идёт к Render по WSS.
- [ ] Первый копирует приглашение в игре. Второй открывает эту ссылку на другом устройстве, вводит другой ник и нажимает «Играть»; оба оказываются в одной комнате.
- [ ] В отдельной проверке вход без приглашения по кнопке «Играть» автоматически подбирает доступную комнату без ручного списка и кода.
- [ ] В комнате отображаются оба игрока; бой начинается от двух настоящих людей, без ботов.
- [ ] На обоих экранах видны движения другого танка, выстрелы, попадания и изменение состояния матча.
- [ ] Счёт, уничтожение танка и завершение/следующий раунд согласованы между устройствами.
- [ ] На обоих компьютерах работают WASD, прицеливание мышью и выстрел ЛКМ.
- [ ] На одном устройстве кратко отключён и восстановлен интернет: видно понятное сообщение, клиент пытается переподключиться. Если матч утрачен после перезапуска сервера, интерфейс сообщает об этом и позволяет войти заново.
- [ ] В кабинете Render всё ещё Free, workspace Hobby, способ оплаты не добавлен; Cloudflare остаётся на Free.

## 8. Если не подключается

| Признак | Проверка и действие |
| --- | --- |
| Первый вход долго ждёт | Откройте `/health`, дайте Render около минуты на пробуждение. Клиент должен показать ожидание и попытки переподключения. |
| `Origin` / 403 / адрес сайта запрещён | Сравните текущий `location.origin` браузера с `ALLOWED_ORIGINS`. Production и preview — разные адреса. Исправьте точное значение, перезапустите Render. |
| Mixed Content / небезопасное соединение | На Cloudflare задайте полный `wss://SERVICE.onrender.com/ws`, повторите сборку. HTTPS-странице нужен WSS. |
| WebSocket 404 | Проверьте `/ws` в URL клиента и правильность hostname Render. |
| В браузере остался старый сервер | После изменения `VITE_SERVER_URL` создайте новую сборку Pages и затем обновите страницу. |
| Render не собирается: `tsc` не найден | Проверьте `Root Directory=server`, наличие `server/package-lock.json`, `NPM_CONFIG_INCLUDE=dev`. Build: `npm ci && npm run build`. |
| Render сообщает, что не найден порт | Сервер должен слушать `0.0.0.0` и автоматический `PORT`. Не указывайте localhost или отдельный публичный WebSocket-порт. |
| Комната исчезла | Сон, deploy или перезапуск очищают память. Вернитесь в меню и нажмите «Играть» для автоматического входа в новую комнату; постоянного хранения нет. |
| Сервис приостановлен из-за лимита | Проверьте Billing/Usage. При условии «без оплаты» дождитесь обновления квоты; не добавляйте карту и не повышайте тариф. |
| Форма требует карту | Прекратите регистрацию/создание сервиса на этом шаге. Публикация без карты для этого аккаунта не подтверждена. |

Чтобы обновить игру, отправьте изменения в `main`: Cloudflare пересоберёт клиент, Render — сервер. Перезапуск сервера прервёт текущие комнаты; обновляйте между матчами. После изменения протокола обновите обе стороны и снова пройдите приёмку.
