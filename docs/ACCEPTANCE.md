# Проверка двух копий игры

**Статус на 17 октября 2026 года:** обе копии прошли HTTPS/WSS, точный Origin и полный трёхминутный матч двух автоматических клиентов: движение, стрельба, урон, уничтожение, возрождение, одинаковые результаты и новый раунд. Обе копии также проверены в настоящем браузере с 3D-сценой; Enzonic — двумя вкладками в общем матче. Совместный матч с двух физических компьютеров через интернет **не проведён**. Полностью завершённой публикация пока не считается.

Render и Enzonic — независимые копии с разными комнатами и матчами. Для общего боя оба игрока должны открыть один и тот же сайт.

Cloudflare у Enzonic — только шлюз. Он должен принимать HTTPS/WSS от браузера и пересылать запросы на фиксированный `http://sgp-two.enzonic.com:25610`. Статика, симуляция и комнаты остаются на Enzonic. **Между Cloudflare и Enzonic используется HTTP/WS без TLS; сквозного TLS до Enzonic здесь нет.** Плохой сертификат нативного адреса этим не исправляется.

## Что выполнено при подготовке

- TypeScript-клиент компилируется, Vite создаёт статические HTML/CSS/JS.
- Серверные тесты используют настоящие WebSocket-соединения и проверяют весь цикл боя: подключение, движение, стрельба, урон, уничтожение, возрождение, окончание раунда и одинаковый результат для клиентов.
- Проверены комнаты на 8 игроков, резерв слота при кратком разрыве, автоматический подбор, строгий Origin, переполнение/неверные сообщения и rate limit.
- Сайт открыт локально двумя браузерными вкладками; оба ника видны в одном матче, часы идут, 3D-карта отображается, управление работает.
- После упрощения меню обе вкладки вошли кнопкой «Играть» без кода и получили одну комнату. Настоящий трёхминутный раунд завершился экраном результатов; кнопка «Ещё один бой» запустила следующий раунд с 03:00.
- npm audit клиента и серверных runtime-зависимостей не обнаружил известных уязвимостей после обновления `ws` до 8.22.0.

Серверные тесты и TypeScript-проверка клиента прошли. Краткий нагрузочный прогон с 8 движущимися и стреляющими WebSocket-клиентами показал RSS около 58 МиБ (сервер и клиенты в одном процессе). Это локальная проба, а не гарантия производительности Render с 0,1 CPU. В этой пробе весь исходящий поток состояний для 8 клиентов составлял около 151 КиБ/с, приблизительно 0,52 ГиБ/час; реальный расход зависит от действий игроков и протокольных накладных расходов.

В тестах время матча и возрождения сокращено через параметры тестового экземпляра. В обычном запуске остаются 180 секунд и 3 секунды. Два автоматических клиента или две вкладки одного ПК не доказывают работу двух физических устройств через публичный WSS.

## Техническая проверка публичных адресов

Настройка размещения описана в [TWO-HOSTS.md](TWO-HOSTS.md). Локально из корня проекта выполните `npm run setup`, затем:

```powershell
npm run verify:remote -- --server https://tank-front.onrender.com --origin https://tank-front.onrender.com
npm run verify:remote -- --server https://tank-front-enzonic.mgladkov669.workers.dev --origin https://tank-front-enzonic.mgladkov669.workers.dev
```

Ожидается PASS с валидным HTTPS-сертификатом, точным Origin, `/health`, `/rooms`, двумя WSS-соединениями и движением. **Обе команды прошли на текущих публичных адресах.** Чужой Origin проверен отдельно: WSS отклонён со статусом 403, разрешение CORS не выдаётся. Браузерная проверка Enzonic тоже пройдена двумя вкладками в матче `V7MTP7`: сцена, оба ника, таймер, без ошибок консоли. Это запись проверки, а не постоянное приглашение.

Полный публичный прогон тоже завершён с `exit 0` на обоих адресах. Повторить его можно теми же командами с дополнительным флагом `--full`: он занимает около трёх минут и использует только обычные действия игроков, без изменения координат/HP/таймера административными командами. Все проверочные подключения после завершения закрыты. Протокол игры на обоих серверах соответствует исходному коммиту `aacb62ad5492888a1810d7bd509bc81053d34fa7`; последующие изменения добавляют шлюз, документацию и проверочные скрипты.

Не отключайте проверку TLS, не принимайте исключение браузера для нативного Enzonic-домена и не используйте HTTP-ссылку как подтверждение WSS. Если Render спит, первый вход может занимать около минуты.

У Workers Free — 100 000 входящих запросов в сутки на аккаунт. Начальный WebSocket Upgrade считается одним запросом; проходящие WebSocket-сообщения обычного Worker не считаются отдельными запросами. Загрузка файлов и новые подключения тоже используют квоту. При исчерпании дождитесь сброса, не подключайте платный план. [Официальный учёт запросов](https://developers.cloudflare.com/workers/platform/pricing/).

## Приёмка двумя друзьями на разных компьютерах

Выполните последовательность **отдельно для Render и Enzonic через Worker**, после успешной технической проверки соответствующего адреса. Нужны два компьютера с клавиатурой и мышью, желательно через разные сети. Второй можно подключить через мобильную точку доступа. Сенсорного управления нет.

1. Оба игрока открывают один и тот же HTTPS-сайт без предупреждений сертификата. A вводит ник и нажимает «Играть». Для однозначной комнаты A копирует «Пригласить» и отправляет ссылку игроку Б.
2. Б открывает приглашение на другом компьютере, вводит другой ник и нажимает «Играть». Оба ника и пинг видны в одной комнате; бой начинается с двух людей, без ботов. Отдельно проверить автоматический подбор без приглашения: достаточно кнопки «Играть», ручного списка комнат нет.
3. Проверить W/S, A/D, прицеливание мышью и выстрел ЛКМ. Перемещения должны быть видны на другом компьютере.
4. В прямой видимости стрелять до уменьшения HP, уничтожения, увеличения счёта стрелка и возрождения жертвы через 3 секунды. За укрытием попаданий нет; танк не проезжает сквозь стены, укрытия и другие танки.
5. Дождаться нуля таймера. Таблицы результатов совпадают на обоих компьютерах. «Ещё один бой» сбрасывает счёт и таймер.
6. На одном компьютере отключить сеть на 5–10 секунд. Проверить сообщение о разрыве и восстановление прежнего игрока. После перезапуска сервера приложение должно сообщить об исчезнувшей комнате и позволить войти снова.
7. Для Render после выхода обоих и 15+ минут простоя проверить новый вход: ожидание пробуждения, затем успешное подключение. Не ставить постоянный внешний опрос ради обхода сна.
8. Проверить в кабинетах Render Free, Enzonic Free и Workers Free, без способа оплаты. Фиксировать ошибки, не повышать тариф.
